    What This Tool Does

    The Image DPI & Metadata Checker reads your PNG, JPG, or WebP files entirely inside your browser and extracts every piece of data you need before sending artwork to a printer or publishing to a print-on-demand (POD) platform. It decodes the raw binary metadata chunks embedded in your file (the pHYs chunk in PNG and the APP0 JFIF segment in JPEG) to retrieve the actual saved DPI value — not a guess. It then calculates the maximum sharp print size at both 300 DPI and 150 DPI, checks for transparent backgrounds using the OffscreenCanvas API, and can even rewrite the DPI metadata and offer a corrected download — all without uploading anything to a server.

    Mathematical Formulas

    All calculations use two core equations:

    • Pixels = Inches × DPI — the foundational relationship between pixel count, physical size, and resolution.
    • Max Print Size = Pixel Dimension ÷ DPI — for example, 4500 px ÷ 300 DPI = 15.00 inches.
    • Centimeters = Inches × 2.54
    • PPM → DPI (from PNG pHYs chunk): DPI = round(pixels_per_meter ÷ 39.3701)

    Technical Specifications

    • PNG pHYs Chunk: Located in the PNG binary after the IHDR chunk. Contains X/Y pixels-per-unit values and a unit flag (1 = meters). The tool divides pixels/meter by 39.3701 to get DPI.
    • JPEG APP0 (JFIF) Segment: Located at byte offset 2 in a standard JPEG. Contains density units (0=aspect, 1=DPI, 2=DPCM) and X/Y density values. The tool handles all three unit modes.
    • Transparency Detection: Uses OffscreenCanvas and getImageData() to scan every 4th byte (alpha channel) of a 300×300 or smaller sampled region. Any alpha < 255 = transparent.
    • DPI Fix (PNG): Locates the existing pHYs chunk and replaces it in-place, or inserts a new 21-byte pHYs chunk before the first IDAT block with correct CRC32 checksum.
    • DPI Fix (JPEG): Modifies the density fields in the existing JFIF APP0 segment, or injects a new JFIF APP0 segment after the SOI marker if none exists.
    • File API: file.arrayBuffer() for binary parsing; URL.createObjectURL() for image loading; Blob + <a download> for file saving.

    Limitations

    • Browser Memory: Very large images (above 100 MP) may be slow to process or cause the browser tab to run out of memory on low-RAM devices.
    • 25-File Cap: Only the first 25 files in a batch are processed. Additional files are ignored with a notice.
    • WebP Transparency: Lossless WebP files support transparency; lossy WebP may not. The tool scans actual pixel alpha values regardless of format.
    • DPI Fix: The "Set 300 DPI" function only modifies metadata tags — it does not resample or upsample pixels. If your image has too few pixels for a given print size, adding a 300 DPI tag will not improve print quality.
    • EXIF DPI: Some cameras write DPI in the EXIF IFD0 rather than the JFIF APP0. This tool reads the JFIF APP0 segment; EXIF-only DPI tags may read as "Not embedded".

    Frequently Asked Questions

    What DPI do I need for professional print quality?

    300 DPI is the standard for professional prints (POD products, art prints, photo books, magazines). 150 DPI is acceptable for large-format prints viewed from a distance (posters, banners). Anything below 150 DPI will appear visibly pixelated or blurry when printed at full size.

    How do I calculate the maximum print size for my image?

    Divide each pixel dimension by the target DPI. A 4500 × 5400 px image at 300 DPI prints at 15.0 × 18.0 inches (38.1 × 45.7 cm). At 150 DPI, that same image prints at 30.0 × 36.0 inches. This tool calculates both automatically and also converts to centimeters.

    How does transparency detection work in this tool?

    The image is drawn onto an OffscreenCanvas and getImageData() samples every pixel's alpha channel value. If any pixel has an alpha value below 255, the image has a transparent background. PNG natively supports full alpha transparency. JPEG does not support transparency. WebP may or may not, depending on the encoding mode.
